# Preferred Fonts

The actual fonts to use, as opposed to the reasoning in `typography-principles.md`.
This file has two tiers: your **base design system pairings** (the default answer
for almost everything) and a broader **exploratory pairing library** (for when a
project calls for something the base system doesn't cover).

## Base Design System pairings (default — use these first)

From the "Base Design System" Figma file (three switchable themes, light mode only
for now). Unless a project has a specific reason to reach into the exploratory
library below, pick one of these three:

| Theme | Palette | Title font | Body font |
|---|---|---|---|
| **Neutral (N3)** — default for most projects | gray + teal | Manrope | Manrope (single family) |
| **Editorial / warm (E1)** | cream + terracotta | Fraunces | Inter |
| **Bold / modern (B1)** | white + violet + lime | Space Grotesk | Space Grotesk (single family) |

## Exploratory pairing library

An 11-pairing palette to browse when a project wants a voice the base system doesn't
have — a one-off piece, a specific mood, something more editorial/expressive than the
system's own three themes cover.

**Important — these are suggestions, not rules.** The "suited for" column is the
mood/category each pairing was built around, not a hard requirement. A pairing
labeled "Technical Terminal" isn't off-limits for a warm editorial piece if it
actually fits once you look at it — treat the label as a starting hypothesis to test
against the actual project, not a gate.

## How to use this file

1. Default to the Base Design System table — pick the theme (Neutral / Editorial /
   Bold) that fits the project, same as always.
2. Reach into the exploratory library only when a project's voice doesn't fit any of
   the three base themes — a one-off landing page, a specific campaign, something
   that wants a mood the system doesn't have.
3. When picking from the exploratory library, treat the "suited for" column as a
   prompt to sanity-check against, not a filter to obey — if a pairing's actual look
   fits the project, use it even if the label doesn't match exactly.
4. See `typography-principles.md` for the reasoning behind pairing choices generally
   (structure, contrast, readability) — this file is just the concrete options.
